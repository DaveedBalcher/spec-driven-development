Day 3: Choose your adventure

3 Days of Spec-Driven Development · Day 3 of 3 · five lessons on four pages, three exercises, a wrap-up · about three hours: 180 minutes including the opener

Specs win. Fix the code, or fix the spec and cascade.

the Linked-Intent Development README (jszmajda/lid), read 2026-09-22

Two days ago you had a chat window. You now have a spec with criteria that can fail, a runner that goes to green on its own, and a critic that audits the result. Today is about handing that to five other people. You will meet three spec frameworks, install exactly one, run one deliberately vague feature brief through it, take a late requirement on the chin, and leave with a comparison card your team can read without taking this course. Pick your track in Lesson 3; your choice sticks for the rest of the day.

Before you start

Day 3 works in day3-work, a copy of your lane at the course root. The shipped sandbox/ is never edited, so what a track wrote is a diff against it. Exercise 1 opens with this block, pasted from the course root. It makes work/ for your answers, copies your lane to day3-work, moves you into it, and copies in the Change C brief and the blank map as ../work/map.md, never over a map you have started. If day3-work already exists, run rm -rf day3-work first: cp -R into an existing folder nests a second copy inside it.

Swift lane 
mkdir -p work && cp -R sandbox/swift day3-work && cd day3-work
cp ../day-3-choose-your-adventure/starter/change-c-brief.md .
{ [ -f ../work/map.md ] || cp ../day-3-choose-your-adventure/starter/map-template.md ../work/map.md; }
ls change-c-brief.md ../work/map.md
Kotlin lane 
mkdir -p work && cp -R sandbox/kotlin day3-work && cd day3-work
cp ../day-3-choose-your-adventure/starter/change-c-brief.md .
{ [ -f ../work/map.md ] || cp ../day-3-choose-your-adventure/starter/map-template.md ../work/map.md; }
ls change-c-brief.md ../work/map.md

Start Claude Code there with claude. day3-work is the day's project root, the folder holding CLAUDE.md, read from ./CLAUDE.md, and your framework is initialized in it. Setup blocks are pasted from the course root; every other Day 3 command runs from inside day3-work. Starters are at ../day-3-choose-your-adventure/starter/; answers go in ../work/.

To reset, quit Claude Code, then from inside day3-work run your lane's line.

Swift lane 
cd .. && rm -rf day3-work && cp -R sandbox/swift day3-work && cd day3-work
Kotlin lane 
cd .. && rm -rf day3-work && cp -R sandbox/kotlin day3-work && cd day3-work

It re-copies the shipped lane, leaves you inside it, and leaves ../work/ untouched. Then, in Exercise 1 or 2, re-run that page's setup copy lines (everything after its cd day3-work) and your track's install-and-init steps from Exercise 1. OpenSpec on your PATH and the LID plugins at user scope survive the reset; BMAD lives in the project, so you run its installer again. A fresh copy has no Change C, so in Exercise 3 run your track's install-and-init from Exercise 1, then Exercise 2 through its self-check (its checkpoint saves time), then cd .. and Exercise 3's setup block. Do not reset between exercises: each one continues from what the one before left.

What today needs
  • Claude Code, signed in. claude --version prints your version; these pages were checked against 2.1.280 on 2026-09-22.
  • Your lane's toolchain from Setup: Swift 6.2, or JDK 17 or later.
  • What your track needs, checked before you choose it. OpenSpec installs with npm, from the registry or a local mirror, and needs Node.js 20.19.0 or later. LID installs inside Claude Code through its /plugin command. BMAD installs with npx bmad-method install and needs Node.js 20.12 or later and uv with Python 3.11 or later; without uv, bmad-build and bmad-build-auto halt, and the offline snapshot cannot supply it.
  • Network access for the install, or the offline snapshot each track's "Network blocked?" box points at. The pages pin OpenSpec 1.13.1, LID commit 831c1959 and BMAD 6.12.0.
  • Two terminal tabs in day3-work, one for the shell and one for Claude Code.

Starter files

Each exercise copies the file it needs from ../day-3-choose-your-adventure/starter/ at the step that needs it, so your framework never reads Change C's acceptance suite while it plans and builds. Exercise 3's two late-change assertions are the exception: its setup copies them in, your framework can read them, and step 3's red, before any code changes, proves they bite.

  • README.md — what each file is for, and which step copies it where.
  • change-c-brief.md — the statement-periods feature brief, with two ambiguities it does not mark.
  • map-template.md — the blank five-question map Exercise 1 copies to ../work/map.md.
  • fixtures/cycle-config.tsv — the cycle-configuration fixture, identical in both lanes.
  • acceptance/ — the hidden Change C suite and the two late-change assertions, in both lanes.
  • late-change.md — the three-sentence late requirement for Exercise 3.
  • comparison-card.md — the blank eight-question card.
  • checkpoints/ — each track's reference planning artifacts, for when planning overruns Exercise 2's 25-minute checkpoint.
  • vendored/ — the offline snapshot of each framework, for a blocked network.
  • track-notes/ and answers/ — page material, never copied into day3-work.
