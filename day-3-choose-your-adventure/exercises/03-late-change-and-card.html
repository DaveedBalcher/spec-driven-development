OpenSpec: start the update (step 2)

Exercise 2 did not archive its change, so archive it first, from the terminal rather than the chat: the archive is a file move plus a spec sync, and the command line does it in one run with no agent turn to wait for. The first line prints the change's name (add-statement-periods if you took the checkpoint). --yes answers the questions the archive can stop on: whether to sync the delta specs into openspec/specs/, and, if a task is still unchecked (for example one that needs git, which cannot run in day3-work), whether to continue anyway.
