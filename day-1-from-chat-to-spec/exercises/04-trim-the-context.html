Reference answers

The six lines that must survive, and the four that feel load-bearing and are not

Quoted from the Swift lane. The Kotlin lane carries the same six facts in different sentences and sections, so check against your own file rather than against these strings.

  1. Run the tests with swift test from the package root. (§ Testing) — without it the agent guesses a test command, and a guessed command that happens to pass is worse than one that fails, because you believe it.
  2. The fixture at Tests/LedgerKitTests/Fixtures/transactions.tsv is the source of truth for expected strings. (§ Fixtures) — where the expected answers live. Fold in Never edit it as you keep it (the Kotlin lane's version of this line already says so), because that stops a failing test being made to pass.
  3. amountMinor is an integer in the currency's minor units; a decimal point never appears in stored data. (§ Money) — the fact that cannot be recovered by reading one file. Fold in Amounts are never floating point from the ISO 4217 paragraph below it, because as written this line does not forbid a floating-point value mid-calculation.
  4. Negative amountMinor is a debit and prints with -; zero or positive is a credit and prints with +. (§ Money) — sign, then symbol, then digits is arbitrary, which is exactly what makes it worth writing down.
  5. Never use NumberFormatter, Locale, ICU or any locale API: all formatting is hand-rolled. (§ Money) — it names the wrong move before the agent makes it. This is the line step 4's rules file already carries.
  6. Run the tests before you say you are done, and quote the final summary line. (§ Testing) — quote rather than summarise is what makes the line checkable. A summary of a test run is an opinion.

The four sections people keep on the first pass, each of which feels responsible and changes nothing the agent does:

  • § Engineering principles and § Working agreements (Kotlin: § Coding standards) — clean code, short functions, no repetition: true of every codebase, specific to none.
  • § Style (Kotlin: § Style guide) — wrong as well as useless: the module's code does the opposite of most of it. A style rule that matters belongs in a formatter.
  • § The ledger-sync tool (Kotlin: § Working with LedgerSync) — accurate, written after a painful week, and not in this repository. Background about a system you cannot touch from here is a document, not an instruction.
  • § About this project and § History (Kotlin: § Project overview and history and § Directory layout) — the agent learns the module by reading it, faster and more accurately than the file describes it, and a directory tree in a standing file is stale the first time somebody adds a folder. History belongs in git.

Two more go for the same reason in whichever lane carries them: the glossary belongs in README.md, and the Kotlin lane's § Git and review workflow belongs in CONTRIBUTING.md. In the Kotlin lane, § Domain rules holds three of your six: keep those and cut the rest, which the types and README.md already carry. The Swift lane's § Code review, § Performance notes, § Accessibility and § Security give good advice about concerns this module does not have. Full key: answers/e4-claude-md-keepers.md.

The reference trimmed file and the reference rules file

Fifteen lines, Swift lane, and the slack under forty is deliberate: Day 2's self-critique needs somewhere to route a finding without the file starting to grow again. The Kotlin lane's copy is the same shape built from its own six lines, with ./gradlew test, Fixtures/transactions.tsv and the glob from step 4.

# CLAUDE.md — LedgerKit

## Testing

- Run the tests with `swift test` from the package root. That is the only test command.
- The fixture at `Tests/LedgerKitTests/Fixtures/transactions.tsv` is the source of truth for expected strings. Never edit it: it is shared byte-for-byte with the other lane.

## Money

- `amountMinor` is an integer in the currency's minor units. It never holds a decimal point, and no code turns it into a floating-point number.
- Negative `amountMinor` is a debit and prints with `-`; zero or positive is a credit and prints with `+`. The sign comes before the currency symbol.

## Before you say you are done

- Run the tests before you say you are done, and quote the final summary line.

The four headings cost four lines and make the file skimmable by whoever has to defend it in six weeks; the mistake they prevent is yours. Nothing in it points at a second file: every long section is a false keep named above, so it was cut rather than filed away. And the highest-value line in the original is not in it, because this reference leaves it to the rules file:

---
paths: ["Sources/LedgerKit/*.swift"]
---

Formatting in this module is hand-rolled: never introduce a locale-aware API (`NumberFormatter`, `DateFormatter`, `Locale`, ICU) into these files.

That move is worth a minute's discomfort. For keeping the rule in CLAUDE.md: an agent can reach for a locale API while editing a test, or a new file the glob does not cover. Against: a rule paid for on every turn and needed on a tenth of them is the tax this exercise teaches you to see. Either answer passes if the file is under forty lines; write down which argument you were making. Longer version, both lanes: answers/claude-md-trim.md.
